## 项目起步：搭建 Phaser 3 环境

### 技术选型
- 选择 Phaser 3 作为游戏框架（HTML5 游戏的事实标准之一）
- 通过 CDN 引入而非 npm 包，省去打包配置
- 开发服务器用 `serve`，极简零配置

### 已掌握的核心概念

**Phaser.Game 配置（main.js）**
- `type: Phaser.AUTO` — 自动选择 WebGL 或 Canvas 渲染器
- `width/height` — 游戏世界的逻辑分辨率（800×600）
- `scale.mode: Phaser.Scale.FIT` — 保持宽高比等比缩放，适配不同窗口
- `autoCenter: Phaser.Scale.CENTER_BOTH` — 画布在页面中居中
- `physics` — 物理引擎配置（Arcade vs Matter），当前暂未启用
- `scene` — 场景注册数组，第一个自动启动

**场景生命周期**
```
constructor → init(可选) → preload(可选) → create → update(每帧)
```
- `constructor`：注册场景的唯一 key
- `create()`：搭建场景内容（放置精灵、文字、按钮等），只执行一次
- `update()`：每帧调用，写持续更新的逻辑（移动、AI、碰撞等）

**坐标体系**
- x 轴 → 从左到右（0 ∼ 800）
- y 轴 → 从上到下（0 ∼ 600）⚠️ 屏幕坐标系 y 向下为正
- 没有真正的 z 轴（Phaser 是 2D 引擎）
- 深度（z-order）用两种机制模拟：
  - 添加顺序：后 add 的对象盖在先 add 的上面
  - `setDepth(数字)`：显式设置深度，值越大越靠前

**Container 容器**
- Container 是一个"组"，把多个对象装在一起
- 里面的对象用相对坐标（相对于容器左上角）
- 整个容器用 `setPosition` 在场景中定位
- 好处：不用手动算每个子对象的绝对坐标

**程序化纹理生成（HomeScene）**
- 用 `Graphics` 画矢量图形（矩形、圆、圆角矩形）
- `generateTexture(key, w, h)` 把图形"烘焙"成纹理
- 之后用 `this.add.image(x, y, key)` 复用，不用每次重画
- `this.textures.exists(key)` 检查纹理是否已存在，避免重复生成

**按钮交互**
- `.setInteractive({ useHandCursor: true })` 让对象可交互
- 事件：`pointerover` / `pointerout` / `pointerdown`
- 视觉反馈：`setTint`（颜色叠加）、`setScale`（缩放）

**Tween 补间动画**
- `this.tweens.add({ targets, y, alpha, duration, ease, onComplete })`
- `showPopup()` 函数：文字向上飘 + 淡出 + 自动销毁
- ease 缓动函数：`Power2` = 先快后慢

**摄像机效果**
- `cameras.main.fadeIn(500, 0, 0, 0)` — 入场淡入动画
- 搭配场景切换使用，提升体验

**场景跳转**
- `this.scene.start('SceneKey')` — 切换到目标场景，当前场景关闭

## 今日心得

### ⭐ 屏幕适配方案（重要知识点）

**问题背景**
游戏画布是 800×600 的逻辑分辨率，但玩家的屏幕可能是 1920×1080、1366×768、甚至是手机竖屏。如果直接把 800×600 的画布扔给不同尺寸的屏幕，要么太小看不清，要么被拉伸变形。

**Phaser 提供的五种缩放模式**

```
模式                    行为                    宽高比    黑边
─────────────────────────────────────────────────────────
NONE                   不缩放，画布固定大小       保持      可能有
FIT           ←常用    等比缩放，完整显示画布      保持      可能有
RESIZE                 画布跟随窗口变化            不保持    无
EXPAND                 只放大不缩小                保持      可能有
ENVELOP                拉伸填满，不保持比例        不保持    无
```

**FIT（本项目使用）**
- 保持游戏画布的宽高比不变
- 等比缩放到窗口能完整容纳的最大尺寸
- 如果窗口比例和游戏比例不一致 → 出现黑边（letterbox 或 pillarbox）
- ✅ 优点：游戏画面不变形，所有内容完整可见
- ❌ 缺点：有黑边，浪费屏幕空间

**实际配置（main.js）**
```js
scale: {
    mode: Phaser.Scale.FIT,           // 等比缩放，完整显示
    autoCenter: Phaser.Scale.CENTER_BOTH,  // 水平和垂直居中
}
```

**关键理解**
- `width: 800, height: 600` 是**逻辑分辨率**，所有游戏坐标都基于它
- 实际显示大小由 scale 配置决定，玩家看到的是缩放后的结果
- `this.cameras.main.width / height` 始终返回逻辑分辨率（800×600），不会变
- 缩放是 Phaser 自动处理的，游戏逻辑不需要关心玩家屏幕的实际尺寸

**何时用哪种模式？**
- 像素风游戏 → FIT，保持像素锐利
- 需要完美填充屏幕的休闲游戏 → RESIZE（需要额外处理 UI 布局）
- 横版卷轴 → FIT 通常够了
- 不同设备差异很大 → 组合策略（FIT 为主体 + 背景图延伸到黑边区）

**与 CSS 缩放的区别**
Phaser 的 scale 是在 Canvas 层面缩放，不是 CSS transform。这样可以保持 Canvas 渲染质量，不会因为 CSS 缩放导致模糊。
