## 二、术语体系定型

经过反复讨论，沉淀了以下术语：

| 术语 | 含义 | 示例 |
|------|------|------|
| **箭头阵** | 管理所有箭头线 + 点阵边界（未实现） | — |
| **箭头线** | Step 的有序数组 | — |
| **步（Step）** | 最小单元，一条有向边 | `Step {start, end, dir, angle, texture}` |
| **尾巴点** | 路径起始格点 | `(col, row)` |
| **路径** | 有向向量数组（压缩） | `[{right,3}, {down,2}]` |
| **有向向量** | 路径的成员，朝一个方向连走 count 步 | `{dir:'right', count:3}` |
| **步序列** | 底层，展开后 | `['right','right','right','down','down']` |
| **头尖点** | 箭头尖端格点，可由尾巴点+路径算出 | `(5,4)` |

### 层级关系

```
箭头阵（未实现）
  └── 箭头线 = Step 的有序数组
        └── 步（最小单元）
```

### 描述 vs 存储

- **描述方式**：尾巴点 + 路径（压缩，用于构造）
- **存储方式**：步序列 Step[]（展开，用于所有操作）

## 三、Step 对象 — 数据结构重构

**旧代码问题**：`_edges`、`_steps`、`images` 三套平行数组，通过索引隐式关联。维护困难，容易出错。

**新设计**：Step 升格为头等对象，一条箭头线就是一个 Step 数组。所有信息封装在 Step 内：

```
Step {
    startCol, startRow   — 起点
    endCol, endRow       — 终点
    dir                  — 方向
    angle                — 旋转角度
    texture              — 'arrow' | 'segment'
    edgeKey              — 无向边 key
    centerCol, centerRow — 中心点（getter）
}
```

## 下午：前进/后退实现 + 碰撞响应 + 踩坑复盘

### 前进（advance）— 两阶段算法

```
① 移动：steps.pop()（去尾）+ steps.unshift(新头)（加头）
② 标箭头：steps[0].texture = 'arrow'，其余 = 'segment'
```

### 碰撞检测集成

每前进一格调用 `isOverlapping()`，返回撞到的对方引用（不是 boolean），碰撞后触发 `_onOverlap(blocker)`。

### 碰撞响应分层

| 方法 | 角色 | 行为 |
|------|------|------|
| `_onOverlap(blocker)` | 撞人方 | 停止 + 永久变红 + 后退回原位 + 通知对方 |
| `_onHit()` | 被撞方 | 保持红 0.3s → 1s 渐变回原色 |

关键设计：碰撞检测（`isOverlapping`）、响应（`_onOverlap`）、移动（`advance`）三层解耦。

## ⭐ 后退（retreat）踩坑复盘

### 问题背景

测试环境：一条直线 + 一个后退目标点 + 后退按钮。目的是独立测试后退逻辑，不被碰撞干扰。

### 第一坑：方向震荡

**现象**：后退无限循环，控制台显示 tail 来回移动，永远到不了目标点。

**原因**：用 `reverse[tail.dir]` 作为后退方向。第一步尾巴是 `down`，reverse='up'，新尾方向是 `up`。第二步尾巴变成 `up`，reverse='down'，新尾变成 `down`。产生 `up ↔ down` 震荡。

```
原始：每次取当前 tail.dir 的反方向 → 方向每步翻转 → 来回震荡
```

### 第二坑：固定反方向失败

**尝试**：改用固定 `reverse[flyDir]` 作为后退方向。

**结果**：直线可退，弯线失败。

**原因**：对于 L 形线（右→下，flyDir=down），固定后退方向=up。但尾巴是向右走的，向上后退无法抵达左边目标点。后退方向和尾巴实际走线方向不一致。

### 正确解：延续尾巴走线方向

**关键认知**：后退不是朝 flyDir 的反方向走，而是**沿着尾巴自己的方向向后延伸**。

```
尾巴 Step(3,3→4,3, 'right')：尾巴朝右走
后退：尾巴应该向左挪 → 新尾 = Step(2,3→3,3, 'right')
                           start 左移一格，方向仍是 right
```

**公式**：`新尾 = Step(tail.start - d, tail.start, tail.dir)`

| 尝试 | 方向来源 | 直线 | 弯线 | 
|------|---------|------|------|
| v1 | `reverse[tail.dir]`（每步变） | ❌ 震荡 | ❌ |
| v2 | `reverse[flyDir]`（固定） | ✅ | ❌ 方向错 |
| v3 | `tail.dir`（延续尾方向） | ✅ | ✅ |

### 教训

1. **测试先行**：用简单环境（单线+按钮）隔离测试，比在复杂场景里排查快得多
2. **不要假设对称**：前进和后退在步序列上的操作是对称的，但方向计算不是简单的 mirror
3. **尾巴朝哪走，后退就往哪退**：关键不是 flyDir，是 tail.dir
