# 2026-06-15 开发日志：箭头阵生成算法重建 + Log 系统完善

## 一句话总结

将箭头阵生成从「校验淘汰制」重建为「递归分治填空法」，从根本上解决了无解问题，同时建立了完整的 Log 系统用于调试和验证。

---

## 一、生成算法的演进

### 1.1 旧版的困境

旧版（校验淘汰制）的核心流程：
1. 随机游走生成线 → `_isSolvable()` 检查 DAG
2. `_isRobust()` 检查对头箭 + 共享中间人 + 全序模拟
3. 不通过就丢弃、重试

**问题**：反复检测仍有遗漏，级联环无法穷尽，且校验过度导致线密度不足（"狗啃"）。

### 1.2 序列逆序构造法（白天完成）

核心思想：**先定顺序，再建图**。

- 生成乱序序列 `[1..N]`，这就是保底解
- 从最后被发射的线开始倒序建线
- 每条线的 flyDir 不能指向已建线（即发射顺序靠后的线）
- 保证：从小到大按序列点，每个箭头前方必为空

**优点**：有解性零开销，不需要 `_isRobust`。

### 1.3 递归分治填空法（晚上完成）

在序列逆序构造法基础上，加入了**多轮递归填空**：

```
第 1 轮：全棋盘生成
↓ 产生空区域
第 2 轮：逐空区域生成（只避开同轮线）
↓ 满填
```

- DotMatrixNew 新增 `getEmptyRegions()` BFS 找连通空区
- 空区域过滤（`_regionFilter`）限制游走范围
- 树形批次编号：`1 → 1-1 → 1-2 → 1-1-1`
- 每批生成后立即重新编号，label 从 1 连续

## 二、Log 系统

### 2.1 分批次统计

dump 文件新增 `batches` 段：

```json
"batches": [
  { "round": "1", "region": "全棋盘", "regionSize": 64, "count": 9, "labels": "[1-9]" },
  { "round": "1-1", "region": "空区(5格)", "regionSize": 5, "count": 2, "labels": "[10-11]" }
]
```

控制台实时输出每轮信息。

### 2.2 空区域连通检测

`DotMatrixNew.getEmptyRegions()` — BFS 四方向连通找所有空区，支持 `_regionFilter` 限定搜索范围。

### 2.3 操作日志（之前的成果）

- `click` / `advance` / `retreat` / `collision` / `dispose` 事件类型
- 事件带 seq 序号、ts 时间戳、detail 详情
- `initialState` vs `currentState` 双快照对比

## 三、Bug 修复

| Bug | 根因 | 修复 |
|-----|------|------|
| 碰撞后撤退越界消失 | `_retreat` 用当前尾部方向延展，原始方向信息丢失 | `_retreatDirs` 栈记录 advance 弹出的方向 |
| retreat 与 advance 竞态 | `_retreat` 没设 `_moving=true` | 入口加锁 |
| 空中线互相碰撞 | `_moving` 线仍被碰撞检测命中 | `!blocker._moving` 过滤 |
| 分步生成跳过批次 | 零产出空区不入队导致编号空档 | 零产出也记录 batch，`-` 标签 |
| 同批内互指 | 同批线不互检 `alreadyPlaced` | 生成后 `_isSolvable` + 重试 |
| `initialSnapshot` 被操作污染 | 延迟到第一次 dump 才快照 | `generateAll` 末尾立即快照 |

## 五、关键认知

**DAG ≠ 任意序安全**：`_isSolvable` 只保证存在至少一条合法序，走错序可能成环。

**从"检测有解"到"构造有解"**：不再试图证明所有序安全，只保证至少有一条路。这是今天最重要的思维转变。

**Log 是第一调试工具**：没有 log 的准确性和可读性，三级联环的根因根本无法定位。
