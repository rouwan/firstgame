# 箭头阵生成方案（第四代 · 当前使用 · 2026-06-17~18）—— 三阶段交替生成

## 核心思想

不试图一次性铺满棋盘，而是用**四种互补的线生成策略交替执行**，每种策略解决一种空间需求。

## 生成序列

`阶段 1 → 阶段 2 → 阶段 3 → 阶段 2 → 阶段 4 → 结束`

- 阶段 1 和 3 各生成 `LINE1_COUNT`（默认 6）条
- 阶段 2 生成到绿色候选用完为止
- 阶段 4 消灭所有 ≥2 格的空区域

---

## 各阶段详情

### 阶段 1：边界线

**箭头点** = 棋盘四条边上的空格。**邻点** = 紧挨箭头点内侧的空格。**飞方向** = 指向棋盘外。

生成逻辑：扫描边界 → 收集 {箭头点, 邻点, flyDir} 候选 → 随机选一个 → 随机选尾巴点 → BFS 最短路径从尾巴走到邻点 → 追加头部。

### 阶段 2：前序线

**箭头点** = 阶段 1 + 阶段 3 所有线的身体旁边的有效空格（绿色高亮）。**邻点** = 箭头往外退一格的空格（蓝色高亮）。**飞方向** = 指向前序线身体。

生成逻辑：从上一阶段的 `_highlightData.candidates` 取候选 → 逐个 BFS → 每条线生成后重新涂色，动态刷新候选池。

**射线安全约束**：箭头沿 flyDir 射出去，整条射线上**必须全是前序线的身体**（不能有空点）。这样前序线飞走后，当前线的路径完全畅通。

### 阶段 3：向内走线

**箭头点** = 同阶段 1（边界空格 + 内侧邻点）。**尾巴** = 从邻点向内随机游走，直到无空位。

生成逻辑：固定头和邻点 → 从邻点出发随机游走，不经过已占格 → 走到尽头的点就是尾巴 → 压缩路径 → 建线。

### 阶段 4：清场

扫描所有空区域（BFS 连通分量），对每个 ≥2 格的空区域，BFS 最短路径连接首尾空格，形成一条线。

完成后棋盘只剩单点空区。

## 底层机制

### 三定点模型

每条线由三个关键点定义：

- **箭头点**（head）— 箭头尖端
- **箭头邻点**（adj）— 紧挨箭头、飞方向上一格
- **尾巴点**（tail）— 线的起始格

邻点 → 箭头点的方向 = flyDir。

### BFS 最短路径

所有线都用 BFS 在四方向空格中找最短路径（只经过未被占的空格），保证线的长度最小、路径没有冗余。

### 涂色高亮系统

每条线生成完后，它的身体四周的空格被标记为：

- **绿色** — 箭头候选点。紧邻前序线身体，可作为下一条线的箭头位置
- **蓝色** — 邻点候选点。箭头位置往飞方向再退一格的空格
- **橙色** — 无效候选点。紧邻身体但退路被堵，不能当箭头

阶段 2 只从绿色点中挑选。

### 全局撤退锁

发生碰撞后，正在撤退的线锁定所有其他线的点击输入，直到撤退完成。防止撤退期间的另一条线点击导致状态冲突。

## 与前三代对比

| 维度 | 三阶段交替（当前） |
|------|------------------|
| 生成方式 | BFS 最短路径（三定点模型） |
| 有解保证 | 序列保证（前序线身体遮挡射线） |
| 覆盖率 | 接近满铺（阶段 4 清场） |
| 线密度控制 | `LINE1_COUNT` 直接控制每批数量 |
| 成功关键 | 射线全扫描 + 前辈线身体遮挡 |

## config.js 相关参数

- `LINE1_COUNT: 6` — 阶段 1 和阶段 3 的线数
- `MATRIX.COLS/ROWS` — 棋盘尺寸
