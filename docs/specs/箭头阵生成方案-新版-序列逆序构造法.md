# 箭头阵生成方案（第二代 · 已归档 · 2026-06-15）—— 序列逆序构造法

## 核心思想

**先定顺序，再建图。** 一个洗乱的序列就是答案——不需要"检测是否有解"，只需要"保证构造成有解"。

## 生成流程

### 第一步：确定发射序列

```
N = 目标线数（如 50）
order = shuffle([1, 2, 3, ..., N])   // Fisher-Yates 洗牌
```

`order[X]` 表示第 X 个被发射的线的编号（同时也是 label）。

### 第二步：逆序建图

从 `order[N-1]`（最后被发射）到 `order[0]`（第一个被发射），倒着建：

```
for i = N-1 down to 0:
    label = order[i]

    已建线集合 = { order[j] | j > i }   // 发射顺序中靠后的，已在棋盘上

    在点阵空闲格点中随机游走，创建线 label：
        - 路径走法同旧版
        - 额外约束：flyDir 的射线不能碰到已建线集合中的任何线
        - 如果尝试多次都满足不了 → 失败，换起点重试

    过了一定重试上限仍未成功 → 放弃这条线，点阵留空
```

### 第三步：正向发射保证

发射时按照 `order[0] → order[1] → ... → order[N-1]` 依次点击。

- 当要发射 `order[X]` 时，`order[0]~order[X-1]` 已经飞走
- 而 `order[X]` 的 flyDir 在生成时只避开了 `order[X+1]~order[N-1]`（尚未飞走的线）
- 那些已经飞走的线，X 不需要避开——它们已经不在了
- 所以 `order[X]` 的 flyDir 前方必然为空 → 100% 畅通

## 数据结构变化

- `this.lines` 仍存 ArrowLine，但 `line.label` = 序列中的位置（1..N）
- `this.order` = 发射序列（shuffle 结果），0-indexed
- `this.orderIndex` = 当前发射到第几个（初始 0）

## getUnblockedLines 变化

按序列顺序，返回 `order[orderIndex]` 那条线（如果它仍然 alive 且 indegree=0）。
自动解图直接按序列点击即可。

## 与旧版对比

| 维度 | 旧版（校验淘汰制） | 新版（序列逆序构造） |
|------|------------------|-------------------|
| 有解保证 | 反复检测、丢弃、重试 | 构造即保证 |
| 环检测 | 需要 `_isSolvable` + `_isRobust` | 不需要 |
| 生成重试 | 大量 discard/retry | 单次构造，少重试 |
| 发射顺序 | 玩家自由选择 indegree=0 的线 | 序列规定（或只允许按序） |
| 线密度 | 受校验影响波动 | 受逆序构造成功率影响 |
| 复杂度 | O(N²) 校验 | O(N²) 构造 |

## 关键约束

生成线 X 时，X 的 flyDir 射线不能碰到任何**已建线**（即发射顺序在 X 之后的线）。
这等价于：X 的 flyDir 只能指向棋盘外或指向发射顺序在 X 之前的线（那些线已经飞走，不在棋盘上）。
