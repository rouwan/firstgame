# 箭头阵生成方案（旧版 · 已废弃）—— 校验淘汰制

## 核心思想

随机游走生成线 → 校验可解性 → 不通过就丢弃 → 重试。

## 生成流程

1. 随机取空闲格点 P0
2. 随机游走：每步在四方向空闲邻居中随机选，加上终止概率
3. 压缩步序列为 path → 创建 ArrowLine
4. 增量校验：
   - `_isSolvable()` — 依赖图拓扑排序，有环则丢弃
   - `_isRobust()` — 对头箭检测 + （多版迭代：共享中间人/逐边/全序模拟），脆弱则丢弃
5. 重试直到棋盘满或连续失败超限

## 依赖定义

从 A 的头尖点沿 flyDir 扫描，第一个碰到的其他线 B = A 依赖 B。

## 主要方法

| 方法 | 作用 |
|------|------|
| `generateOneLine()` | 随机游走生成一条线 |
| `generateAll()` | 循环生成 + 增量校验 + 重试 |
| `_isSolvable()` | Kahn 拓扑排序，检查 DAG |
| `_isRobust()` | 对头箭检测（经历多版演进） |
| `_isLoop()` | 自己挡住自己检查 |

## 演进历史

1. **初始版**：只做 `_isSolvable`，线多但玩家操作后常成环
2. **对头箭版**：加反向箭检测，仍有多中间人级联环
3. **逐边越位版**：每条边 A→B 扫过 B 检查 C→*A，漏双中间人
4. **全序模拟版**：模拟拓扑移除全过程，线太少（狗啃）
5. **最终版**：退回对头箭 + 限制玩家只能点 indegree=0 的线

## 问题

- 反复校验淘汰 → 部分场景线密度不足
- 多中间人级联环无法穷尽检测
- 生成复杂度和线密度不可兼得
