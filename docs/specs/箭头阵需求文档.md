# 箭头阵需求文档

> 本文档定义箭头阵（ArrowMatrix）和点阵（DotMatrix）的数据模型、生成算法和可解性校验。
> 代码实现：[js/objects/ArrowMatrixNew.js](../../js/objects/ArrowMatrixNew.js) / [js/objects/DotMatrixNew.js](../../js/objects/DotMatrixNew.js)

---

## 〇、术语表

| 术语 | 英文 | 含义 |
|------|------|------|
| **点阵点** | grid point / dot | 点阵上还没有被任何箭头线占据的格点。后续轮次可以在其上生成新线。 |
| **占据点** | occupied point | 点阵上已被某条箭头线的身体或尖端覆盖的格点。 |
| **边界** | boundary | 棋盘的四条边（left=0, right=COLS-1, up=0, down=ROWS-1）。箭头指向边界 = head 紧挨边缘，flyDir 方向一步出界。 |
| **飞行方向** | flyDir | 箭头线头部的指向，也是箭头前进的方向（right/left/down/up）。 |
| **射线** | ray | 从箭头头部沿 flyDir 方向延伸到棋盘边界的整条线段。 |
| **空点** | empty point | 同"点阵点"。 |
| **空区域** | empty region | 四方向连通的一片点阵点集合。BFS 找到的连通分量。 |
| **单点空区域** | singleton region | 只有一个格点的空区域。无需继续填空。 |
| **对头箭** | head-on arrows | 两条箭头在同一射线上 flyDir 相反。终将互指死锁。 |
| **跨区域对头箭** | cross-region head-on | 同一轮次的两个不同子区域生成的线，恰好在同射线上相向飞行。生成时彼此不可见，合在一起形成死锁。修复：射线全扫描检查对头箭。 |
| **依赖** | dependency | 线 A 的射线第一个碰到的其他线 B。A 依赖 B（B 必须先飞）。 |
| **轮次** | round / batch | 生成一轮。第 1 轮全棋盘，后续每轮在空区域内生成。编号规则 `1 → 1-1 → 1-2 → ...`。 |
| **解图序列** | solve sequence | 预先确定的合法发射顺序。按此序点击必通关。 |

## 一、概述

### 1.1 对象层级

```
场景 (GameScene)
  └── 箭头阵 (ArrowMatrixNew)
        │  管理容器 + 生成逻辑
        │
        ├── 点阵 (DotMatrixNew)
        │     grid[row][col] = { image, owner }
        │     格点占用的唯一真相源
        │
        └── 箭头线[] (ArrowLine[])
              └── 步[] (Step[])
                    连接相邻格点的有向边
```

### 1.2 核心原则

> **点阵是格点占用的唯一真相源。** 任何对格点的占用/释放/查询都走 DotMatrix，不自己维护。

## 二、DotMatrixNew — 点阵

### 2.1 数据结构

```js
grid[row][col] = {
    image: Phaser.Image,     // dot 纹理的 Image 对象
    owner: ArrowLine | null, // 占用者（唯一真相源）
}
```

### 2.2 接口

| 方法 | 职责 |
|------|------|
| `draw(container)` | 绘制所有格点圆点 |
| `getRandomAvailablePoint()` | 随机返回一个空闲格点 |
| `getAvailableNeighbors(col, row)` | 返回四方向上所有空闲邻居（含方向） |
| `occupy(col, row, line)` | 占用；同线幂等，异线返回 `{ok:false, conflict}` |
| `release(col, row, line)` | 释放（仅当是自己占的） |
| `getOccupant(col, row)` | 查询占用者 |
| `inside(col, row)` | 是否在网格范围内 |

### 2.3 为什么允许空点

旧设计要求"全线覆盖全点阵"，新设计不强求。因为随机游走生长时，一些点会成为孤点（四方向全被占），这些空点是天然的，不影响谜题。空点不是 bug，是留白。

## 三、ArrowMatrixNew — 箭头阵

### 3.1 生成算法：随机游走

核心思路：**从可用点出发，每一步从空闲邻居中随机选一个前进，直到随机终止或无处可走。**

```
_generateOneLine():
  ① dotMatrix.getRandomAvailablePoint() → P0
  ② P0 四方向找空闲邻居 → 随机选 P1 → 第一个 Step
  ③ 循环：
       当前点 P 的空闲邻居 = 备选
       随机决定：继续走 / 终止（概率 = CONFIG.ARROW_MATRIX.TERMINATE_PROB）
         → 继续：随机选邻居 → 加 Step → 前进
         → 终止：结束，最后一步是箭头
       如果无邻居 → 强制终止
  ④ 压缩 steps → path 格式 → new ArrowLine(...)
```

**与旧方案的关键差异：**

| 维度 | 旧（模板方案） | 新（随机游走） |
|------|---------------|----------------|
| 生成方式 | 固定模板（横扫/蛇形/螺旋） | 随机游走，每一步都有随机性 |
| 随机性 | 无，玩家一眼看穿 | 同一参数每次不同阵 |
| 全覆盖 | 强制 | 不强求，允许空点 |
| 依赖关系 | 人工设计 | 多条线自然穿插，依赖自己涌现 |

### 3.2 三层防护：保证谜题合规

箭头阵生成有三层校验，缺一不可：

```
                ┌──────────────────────┐
                │  ① DotMatrix 占用管理  │ ← 防点重合
                │    构造时注册格点       │
                │    飞行时先查后占       │
                └──────────┬───────────┘
                           │ 通过
                ┌──────────▼───────────┐
                │  ② 回环检测 _isLoop   │ ← 防线咬尾
                │    从箭头尖端沿 flyDir │
                │    射线到棋盘边，       │
                │    碰到自己 → 丢弃      │
                └──────────┬───────────┘
                           │ 通过
                ┌──────────▼───────────┐
                │  ③ DAG 校验 _isSolvable│ ← 防死锁环
                │    构建依赖图 →        │
                │    拓扑排序 →          │
                │    有环 → 清空重来     │
                └──────────────────────┘
```

#### 层1：DotMatrix 占用管理

每条 ArrowLine 构造时调 `_registerPoints()`，逐格调 `dotMatrix.occupy()` 注册。已被占用则报冲突。从根本上杜绝点重合。

#### 层2：回环检测 `_isLoop()`

```
从箭头尖端 (headCol, headRow) + flyDir 方向 逐格前进，
直到出棋盘边界。
如果途中任意一个格点的 occupier === 自己 → 回环 → 丢弃。
```

为什么是整条射线而不只是下一步？因为玩家预期箭头指向的方向不应该有自己的身体，不只是第一步。

#### 层3：DAG 可解性校验 `_isSolvable()`

**依赖定义：** 从线 A 的箭头尖端沿 flyDir 逐格走，第一个碰到的其他线 B，就是 A 依赖 B（B 必须先飞才能给 A 让路）。

```
依赖图构建：
  for 每条线 A：
    从 A.head 沿 flyDir 射线
      第一个 occupier !== A 且 !== null → B
      A 依赖 B

拓扑排序（Kahn 算法）：
  计算每条线入度 → 入度=0 入队
  循环出队：
    该线的依赖者的入度 -1
    新入度=0 入队
  全部节点被访问 → DAG → 有解
  有节点未访问 → 有环 → 无解

无解 → 清空全部线 → 重新 generateAll()（最多 20 次）
```

**依赖图示例：**

```
   线0 → 线1     线0 依赖线1，线0 也依赖线2
   ↓     ↓      线1 依赖线3，线2 依赖线3
   线2 → 线3     合法解：3→1→2→0 或 3→2→1→0（线1和线2顺序可互换）
```

### 3.3 完整流程

```
generateAll(onProgress):
  loop (最多 20 次):
    ① 逐条调 generateOneLine() 直到 isDone()
    ② _isSolvable()
       → DAG 且 visited == 线数 → 成功返回
       → 有环 → _clearAll() → 下一轮
  超上限 → 不校验直接返回（至少有一个阵）
```

终止条件（`isDone()`）：

| 条件 | 含义 |
|------|------|
| `getAvailablePoints().length === 0` | 点阵全满 |
| 所有可用点四方向都被占 | 只剩孤点，无法起点 |

回环不算终止——`generateOneLine()` 返回 null 但 `isDone()` 仍为 false → `generateAll` 继续试。

### 3.4 参数

| 参数 | 位置 | 含义 |
|------|------|------|
| `TERMINATE_PROB` | `CONFIG.ARROW_MATRIX` | 随机游走每步终止概率（0~1，越小线越长） |
| `MAX_ATTEMPTS` | `generateAll()` 内部 | 无解重试上限（当前 20） |
| `failStreak >= 50` | `generateAll()` 内部 | 连续回环/失败的安全阀 |

### 3.5 方法清单

| 方法 | 职责 |
|------|------|
| `drawDots()` | 委托 DotMatrix 绘制点阵 |
| `generateOneLine()` | 随机游走生成一条线（含回环检测） |
| `generateAll(onProgress)` | 循环生成 + DAG 校验（含无解重试） |
| `isDone()` | 是否生成已结束 |
| `setPosition(x, y)` | 整体定位 |
| `_isLoop(line)` | 回环检测 |
| `_isSolvable()` | DAG 可解性校验 |
| `_clearAll()` | 清空全部线重置 |

## 四、与旧版的对比

| | 旧版 ArrowMatrix/DotMatrix | 新版 ArrowMatrixNew/DotMatrixNew |
|------|------|------|
| 点阵 | 无独立对象 | DotMatrixNew 唯一真相源 |
| 生成 | sweepFill / regionFill（模板） | generateAll（随机游走） |
| 全覆盖 | 强制 | 不强求 |
| 回环 | 无检测 | 射线检测 + 丢弃 |
| 可解性 | 无校验 | DAG 拓扑排序 |
| 点重合 | 事后 warn | 构造时当场拒绝 |

旧文件 `ArrowMatrix.js` / `DotMatrix.js` 保留作为参考，新功能全部走 `New` 版。
