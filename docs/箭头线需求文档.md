# 箭头线需求文档

> 本文档定义箭头线（ArrowLine）的数据模型和功能，作为开发和代码审查的基准。
> 代码实现：[js/objects/ArrowLine.js](../js/objects/ArrowLine.js)

---

## 一、核心数据结构 ✅ 已整理

### 层级关系

```
箭头阵（未实现）  ← 管理所有箭头线 + 点阵边界
  └── 箭头线 N    ← 由步序列构成
        └── 步    ← 最小单元：一条有向边
```

### 1.1 Step — 步

**箭头线的最小单元**。一个步 = 点阵上相邻两格点之间的有向边。

```
Step {
    startCol, startRow   — 起点（格点）
    endCol, endRow       — 终点（格点）
    dir                  — 方向 'right'|'down'|'left'|'up'
    angle                — 旋转角度
    texture              — 纹理类型 'arrow'|'segment'
    edgeKey              — 无向边 key（碰撞用）
    centerCol, centerRow — 中心点（getter，两端点中点）
}
```

### 1.2 箭头线

**箭头线是 Step 的有序数组**。所有操作（绘制、判定、前进）都在步序列上执行。

```
箭头线 = [Step, Step, Step, ..., Step]
          ↑ 头（箭头）             ↑ 尾（线段）
```

#### 描述方式：尾巴点 + 路径

步序列是运行时数据，构造时用更简洁的**尾巴点 + 路径**来描述：

```
尾巴点(col, row) + [{dir, count}, ...]   ──展开──▶  Step[]
```

尾巴点和路径是**描述方式**（压缩），步序列是**存储和操作方式**（展开）。

### 1.3 尾巴点

```js
尾巴点 = (col, row)
```

- 路径第一个有向向量的出发点
- 整条线的尾部端点
- 代码：`_startCol, _startRow`

### 1.4 路径

```js
路径 = [{ dir, count }, ...]
```

- **有向向量**的数组（路径的成员叫有向向量）
- 每个有向向量：朝 `dir` 方向连走 `count` 格，直到转弯
- 代码：`_path`

#### 路径展开：路径 → 步序列

路径是压缩表示，绘制/移动前需展开为**步序列**：

```
路径 [{right,3}, {down,2}]
         ↓ 展开
步序列 ['right','right','right','down','down']
```

| 术语 | 层级 | 示例 |
|------|------|------|
| **路径** | 输入级，压缩 | `[{right,3}, {down,2}]` |
| **有向向量** | 路径的成员 | `{dir:'right', count:3}` |
| **步序列** | 底层，展开后 | `['right','right','right','down','down']` |
| **步** | 最小单位，走一格 | `'right'` |

> **有向向量 vs 步**：有向向量是"朝某方向连走 count 步"（压缩），步是"朝某方向走一格"（最小单元）。一个有向向量 = count 个步。例如 `{right,3}` = `['right','right','right']`。

- 代码：`_path`（路径）、`_steps`（步序列）
### 1.5 由核心数据推导的成员

以下成员**不是独立数据**，而是由 尾巴点 + 路径 计算得出：

| 推导项 | 含义 | 计算方式 |
|--------|------|---------|
| **头尖点** `(headCol, headRow)` | 箭头尖端的位置 | 尾巴点 + 累加每个有向向量的 dx/dy |
| **flyDir** | 箭头指向的方向 | 路径最后一个有向向量的 dir |
| **步数序列** `_steps` | 逐步方向数组 | 路径展开：`right×3 → ['right','right','right']` |
| **边列表** `_edges` | 每步占据的无向边 | 从尾巴点沿 steps 逐步生成 |
| **images 数组** | 渲染用的 Image 对象 | `_buildImages()` 根据 steps 创建 |

### 1.6 存储约定（复位用）

构造时保存 `尾巴点 + 路径 + 坐标映射(toX/toY/DIR)`，`_reset()` 时用这些值调用 `_buildImages()` 即可完全重建。

### 1.7 序号约定

- **序号 0** = 头（基础箭头），位于路径末端，朝 flyDir
- **序号 N-1** = 尾（最后一个线段），位于路径始端
- `images[0]` = 头，`images[N-1]` = 尾

## 二、功能

### 2.1 绘制（9 步）✅ 已整理

**输入**：尾巴点 `(tailCol, tailRow)` + 路径

以 `尾巴点(2,2) + [{right,3}, {down,2}]` 为例：

---

**① 展开**：路径 → 步序列 → Step 对象

```
路径 [{right,3}, {down,2}]
         ↓ 展开
步序列 ['right','right','right','down','down']
         ↓ 封装
Step 对象 [{start:(2,2), end:(3,2), dir:'right', texture:'segment'}, ...]
```

每个 Step 包含：起点、终点、方向、角度、纹理类型、边 key。一个 Step = 点阵上的一个步。

---

**② 定边**：从尾巴点出发，每步走一格，确定该段占据的两个格点

```
尾巴点 (2,2)
  步0 right → 边 (2,2)-(3,2)，落脚 (3,2)
  步1 right → 边 (3,2)-(4,2)，落脚 (4,2)
  步2 right → 边 (4,2)-(5,2)，落脚 (5,2)
  步3 down  → 边 (5,2)-(5,3)，落脚 (5,3)
  步4 down  → 边 (5,3)-(5,4)，落脚 (5,4)  ← 最后一步，即头尖点
```

---

**③ 定纹理**：最后一步 → `'arrow'`，其余 → `'segment'`

---

**④ 定中心点**：每步取两个格点的中点 `((c1+c2)/2, (r1+r2)/2)`，图像放于此

---

**⑤ 格坐标 → 像素坐标**：`toX(col)` / `toY(row)`

---

**⑥ 定角度**：`right→0° down→90° left→180° up→-90°`

---

**⑦ 创建图像**：`scene.add.image(px, py, 纹理).setAngle(角度)`

---

**⑧ 排序**：反转 → `images[0]=头, images[N-1]=尾`

---

**⑨ 标签**（DEV 模式下）：在头尖点上方创建 Text，`ArrowLine.DEV = true/false` 控制显隐

### 2.2 点阵内判定 ✅ 已整理

**`isInside() → boolean`**

判定所有步的端点是否严格在点阵格子 `[0, COLS-1] × [0, ROWS-1]` 内。任一端点出界返回 `false`。

> 接口已就位，具体使用场景（构造校验 / 关卡数据校验）待后续确定。

---

### 2.3 重合判定 ✅ 已整理

**`isOverlapping() → ArrowLineNew | null`**

判断自身是否与全局中其他箭头线共享格点。如有重合返回对方引用，无则返回 `null`。

---

### 2.4 前进 ✅ 已整理

**触发**：点击箭头线任意段 → `advance()`

**算法（两阶段）**：

```
① 移动：steps.pop()（去尾）+ steps.unshift(新头)（加头）
② 标箭头：steps[0].texture = 'arrow'，其余 = 'segment'
③ 重绘：_buildImages() + _makeLabel()
④ 重复，直到尾离开点阵 → _dispose()
```

**结束条件**：尾巴点离开点阵（两个端点都不在格子范围内）。

**碰撞**：每一步后调用 `isOverlapping()`，如果重合 → 调用 `_onOverlap()`（当前临时实现为停止，后续扩展）。

实现方式：毁建（销毁 + 生成），不是移动。避免转弯时角度 tween。

### 2.5 重合响应 ⚠ 临时实现

**`_onOverlap()`** — 前进过程中与其他箭头线重合时触发。

当前临时行为：自身停止，并调用对方的 `_onHit()`。撞人方的永久变红等完整响应见 2.7。


---

### 2.6 后退 🔒 暂缓

尾（序号 N-1）沿尾的方向反向退一格。身体每段删除自己，在"后面序号"的上一帧位置生成（含角度）。

**暂缓原因**：需求混乱导致开发反复，先吃透现有功能再推进。

### 2.7 撞别人反应 ✅ 已整理（临时）

**`_onOverlap(blocker)`** — 前进中撞到其他线时触发。

行为：永久变红 → 后退回初始尾巴点（蛇形逆向）→ 停在原位。同时调用对方 `_onHit()`。

### 2.8 被别人撞反应 ✅

**`_onHit()`** — 被其他箭头线碰撞时触发。

行为：瞬间变红 → 保持 0.5s → 渐变 2s 回原色 → 恢复。

| 参数 | 含义 |
|------|------|
| **保持时间** | 纯红状态持续多久 |
| **渐变时间** | 红 → 原色的过渡时长 |

## 三、碰撞规则 ⚠ 旧代码逻辑，待新架构整理

- 每条箭头线占据若干"无向边"（两个相邻格点之间的连接）
- 飞行中，头要进入的边已被其他箭头线占据 → 触发碰撞
- 碰撞后：撞人者永久红 + 复位，被撞者闪烁恢复
