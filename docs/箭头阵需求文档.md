# 箭头阵需求文档

> 本文档定义箭头阵（ArrowMatrix）的数据模型和功能，作为开发和代码审查的基准。
> 代码实现：[js/objects/ArrowMatrix.js](../js/objects/ArrowMatrix.js)

---

## 一、概述

### 1.1 什么是箭头阵

**箭头阵 = 点阵 + 箭头线数组**。它是箭头的管理容器，负责生成点阵上的所有格点，然后生成一组箭头线覆盖这些格点。

### 1.2 层级关系

```
箭头阵          ← 本对象，管理点阵 + 所有箭头线
  ├── 点阵      ← 格点矩阵（cols × rows 个圆点）
  └── 箭头线[]  ← 多条箭头线，形成一个覆盖全点阵的图案
        └── 步  ← 最小单元，见箭头线需求文档
```

箭头阵在游戏对象层级中的位置：

```
场景 (GameScene)
  └── 箭头阵 (ArrowMatrix)
        ├── Container（Phaser 容器，统一位移/缩放）
        ├── 点阵（Image[]，每个格点一个圆点纹理）
        └── 箭头线[]（ArrowLine[]，通过 Container 间接持有图像）
```

## 二、核心数据结构

### 2.1 构造参数

```js
ArrowMatrix(scene, cols, rows, spacing)
```

| 参数 | 含义 | 来源 |
|------|------|------|
| `scene` | Phaser 场景引用 | `this`（在场景 create 中传入） |
| `cols` | 点阵列数（横向格点数） | `CONFIG.MATRIX.COLS` |
| `rows` | 点阵行数（纵向格点数） | `CONFIG.MATRIX.ROWS` |
| `spacing` | 相邻格点的像素间距 | `CONFIG.MATRIX.SPACING` |

### 2.2 内部状态

| 成员 | 类型 | 含义 |
|------|------|------|
| `this.lines` | `ArrowLine[]` | 所有箭头线的引用数组 |
| `this.container` | `Phaser.GameObjects.Container` | 统一容器，所有子对象 add 到这里 |
| `this.toX(col)` | `function` | 格列号 → 像素 x（以矩阵中心为原点） |
| `this.toY(row)` | `function` | 格行号 → 像素 y（以矩阵中心为原点） |
| `this.DIR` | `object` | 方向映射表，`{right, down, left, up}` 各含 `{dx, dy, angle}` |

### 2.3 坐标映射

格坐标以矩阵中心为原点，像素坐标 = 格坐标 × spacing 减去半个矩阵宽/高：

```js
toX = (col) => col * spacing - matrixW / 2
toY = (row) => row * spacing - matrixH / 2
```

其中 `matrixW = (cols - 1) * spacing`，`matrixH = (rows - 1) * spacing`。

这是点阵和所有箭头线共享的坐标系，保证格坐标到像素坐标的映射一致。

### 2.4 方向映射

```js
DIR = {
    right: { dx:  1, dy:  0, angle:   0 },
    down:  { dx:  0, dy:  1, angle:  90 },
    left:  { dx: -1, dy:  0, angle: 180 },
    up:    { dx:  0, dy: -1, angle: -90 },
}
```

该映射表传给每条箭头线的构造函数，统一方向定义。

## 三、功能

### 3.1 生成点阵 — `drawDots()` ✅

**职责**：在 `cols × rows` 的所有格点位置创建圆点图像，加入 container。

**算法**：双重循环遍历所有 `(col, row)`，每个位置创建一个 `'dot'` 纹理的 Image。

```
for row in 0..rows-1:
    for col in 0..cols-1:
        scene.add.image(toX(col), toY(row), 'dot') → container.add()
```

**纹理来源**：`'dot'` 纹理在 HomeScene 中通过 `generateTexture` 生成，是半径 `CONFIG.TEX.DOT_RADIUS` 的实心圆。

---

### 3.2 生成箭头线数组 — `sweepFill()` ✅

**职责**：生成一组箭头线，**覆盖点阵上的所有格点**。

#### 3.2.1 全覆盖定义

> 一组箭头线**全覆盖**点阵 ⇔ 每个格点至少被一条线的 Step 经过。

全覆盖是最低要求。不同的生成策略会产生不同形态的箭头阵列（横扫、蛇形、螺旋等）。

#### 3.2.2 当前实现：横扫模式

每行生成一条右向箭头线，从最左列横扫到最右列：

```
行 0: 尾巴点(0, 0) + [{right, cols-1}]  → 线从 (0,0) 到 (cols-1, 0)
行 1: 尾巴点(0, 1) + [{right, cols-1}]  → 线从 (0,1) 到 (cols-1, 1)
...
行 R-1: 尾巴点(0, R-1) + [{right, cols-1}] → 线从 (0,R-1) 到 (cols-1, R-1)
```

```
示意图（5列×3行）：

  •──•──•──•──•    ← 行 0，箭头线 0
  •──•──•──•──•    ← 行 1，箭头线 1  
  •──•──•──•──•    ← 行 2，箭头线 2
  
  每个 • 是一个格点，每条 ── 是一个 Step
```

**参数**：
| 参数 | 值 | 含义 |
|------|-----|------|
| `tailCol` | `0` | 尾巴点在每行最左 |
| `tailRow` | `row` | 当前行 |
| `path` | `[{dir:'right', count:cols-1}]` | 右向横扫整行 |
| `label` | `"0", "1", ...` | 行号（DEV 模式显示） |

#### 3.2.3 生成算法设计原则

##### 核心诉求：同一范式，不同阵

覆盖策略不能只是一种布局，而必须是**一个带随机参数的生成器**——同一范式每次生成不同阵，让玩家需要重新分析依赖关系。

##### 反例：哈密顿路径 + 分段（已废弃）

尝试过一条哈密顿路径切多段的方案：

```
一条蛇形路径 → 在转弯处切断 → 3~5 条首尾相接的线
```

两个致命问题：

1. **相邻段共享端点** — 段 N 的最后一步终点 = 段 N+1 的起点。静态全部是重叠状态，开局就判定碰撞。
2. **解永远是逆序** — 段序列 `A→B→C→D`，解法永远是 `D→C→B→A`。玩家第一次就学会，换个模板还是同一件事——没有推理价值。

##### 正例：分区 + 飞向交叉

```
网格分成互不重叠的若干区域
每个区域生成一条线（蛇形填满该区域）
线的 flyDir 指向另一个区域（而非呆在自己区域内）
```

这样：
- **初始无重叠** — 区域互不重叠，线之间静态共存
- **飞行产生依赖** — 线飞向另一区域 → 必须等那个区域的线先飞走 → 产生真正的"谁先谁后"推理

##### 依赖图必须是 DAG，但不能是简单链

| 依赖形状 | 解的数量 | 趣味 |
|----------|----------|------|
| 无依赖（横扫） | N! 种 | 无聊，不叫谜题 |
| 链式依赖 A→B→C→D | 1 种 | 无聊，逆序即可 |
| DAG，多分支 | 多种合法解 | ✅ 有趣，需要推理 |

DAG 多分支举例：

```
   A ──→ B
   ↓     ↓
   C ──→ D
```

- A 挡了 B 和 C → A 必须先飞
- B 挡了 D、C 挡了 D → B 和 C 都要在 D 之前飞
- B 和 C 之间无依赖 → 先谁都可以
- 合法解：A→B→C→D 或 A→C→B→D

#### 3.2.4 当前覆盖策略

| 策略 | 方法 | 状态 |
|------|------|------|
| **横扫** | `sweepFill()` | ✅ 保留，用作最简单的入门关 |
| **分区填充** | `regionFill(opts)` | 🔨 进行中 — 随机分区 + DAG 依赖 |

### 3.3 容器定位 — `setPosition(x, y)` ✅

**职责**：将整个箭头阵（点阵 + 所有箭头线）作为一个整体移动到指定像素坐标。

因为所有子对象都 add 到同一个 Container，移动 Container 即可整体位移。

```
setPosition(x, y) → this.container.setPosition(x, y)
```

典型用法：`matrix.setPosition(width/2, height/2)` 将箭头阵居中于屏幕。

## 四、与箭头线的协作关系

### 4.1 创建箭头线时传入什么

箭头阵在生成每条箭头线时，将自己的共享资源传入：

```
new ArrowLine(
    scene,        // Phaser 场景
    container,    // 箭头阵的 container（线把自己的图像 add 进去）
    tailCol,      // 尾巴点（格坐标）
    tailRow,
    path,         // 路径描述
    toX, toY,     // 坐标映射函数
    DIR,          // 方向映射表
    label         // DEV 标签
)
```

### 4.2 谁拥有什么

| 资源 | 所有者 | 说明 |
|------|--------|------|
| Container | ArrowMatrix | 唯一的 Phaser Container |
| 点阵 Image | ArrowMatrix（通过 container） | `drawDots()` 创建 |
| 箭头线 Image | ArrowLine（通过 container） | `_buildImages()` 创建 |
| 箭头线 Step 数据 | ArrowLine | `this.steps[]` |
| 全局线注册 | ArrowLine（静态） | `ArrowLine._all[]` |

箭头阵**不直接管理**箭头线的内部状态（步序列、碰撞等），只负责创建和持有引用。

## 六、待澄清

- 箭头阵是否需要支持**动态添加/删除**箭头线（例如游戏中新生成或消除线）？
- 全覆盖策略是否需要支持**用户选择**（如首页选横扫 vs 蛇形）？
- 是否需要**验证功能**：检查某组线是否真的全覆盖了点阵？
