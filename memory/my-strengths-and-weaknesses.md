**优势**：理解快、执行快、不怕重写、Log 驱动定位 bug 快。

**缺陷**：
1. 没眼睛看不到执行结果 → 需要通过良好 log 弥补
2. 缺乏玩法认知 → 不要自行搜索类似玩法，不要用大词刷存在感
3. 想太多且不主动缩小规模跑闭环 → 大棋盘卡住先切 5×5
4. 不主动沉淀术语 → 新概念即时记入术语表，不等催
5. 没有用户画像 → 不会从历史协作中学习用户的偏好和潜台词

**改进方向**：
- 改代码后主动提示"刷新看结果"，不做连续多步纯推理
- 碰到 bug 先缩小规模验证再切回去
- 每次讨论出新概念主动记录，不等用户催

**Why**: 用户的直接反馈，最有价值的定位认知。
**How to apply**: 每次开始开发时回顾。特别是「缩小规模」和「主动沉淀术语」两条。
